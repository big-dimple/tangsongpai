### pending、confirmed与持久事实分开

这里定义表现语义，不新增存档字段：

- **draft pending**：编辑、悬停、选数不足或不合格；只有静态选择/计数，不发source/travel。
- **draft confirmed**：既有UI已接受明确且当前合法的目标/副组/支付或释放选择，但尚未提交出牌。这时可启动source→travel→attached idle，表示“待作用”，不扣资源、不显示已兑现；换主手/目标后须重新验证。
- **saved / resolved**：只有成功且非duplicate的原命令回执、实际留牌落位或ScoreTrace事件可驱动consume/release。秦琼领域resolution=pending是“已保存、下一手待判”，辛弃疾pendingRefill是真实已保存候选，不能与未保存草稿混为一谈，更不能靠取消动效撤销业务状态。

|状态|进入/退出、锚点与所有权|
|---|---|
|source|新的合法draft confirmed且真实选择集合改变，头像/技能按钮短响应一次；源优先取用户实际操作且当前可见的入口，否则直接静态标记，不猜屏幕坐标|

|attached idle|牌边/组边保持低密度流动直到失效或真实提交；样例必须连续可见至少3秒，不以一次闪光或静态文本充数。只有一个英雄意图owner，整手效果只一份，苏轼副组按真实ids|
