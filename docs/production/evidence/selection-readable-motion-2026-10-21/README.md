## 实际不足和具体修正

原 main 中朱印约44px，落在复杂衣纹上；四段合计约520ms，印峰与外迸缺少可读时间。确认按钮在这段时间呈灰色忙态，本体不参与动作。墨痕虽有曲线，但细节和短尾容易只读成一条跳线。这里没有把“存在节点/逐帧可见”当作原速可感知性已经满足。

- **A 纸上灵尘**：重新分配选角限定的外围带，暖金、青绿、淡白沿人物两侧疏密漂移，前景较近、后景较细。保留低频错峰明暗。原画的桌面点击区含宽空白，旧通用遮挡扫描曾将外围也一并隐藏；现在仍保护实际图片与所有文字/操作按钮，只允许原画空白边距承载非交互微粒。即使原画尚在加载，拟合肖像区域也始终受保护。
- **B 游龙墨痕**：760ms 单次有方向掠笔，笔腹约13–24px，有收尖、干笔分段和六个短碎笔。局部纸色衬边让深墨在繁复衣物上有边界，不靠整屏变暗或旋转光环。
- **C 朱印定魂**：默认1200ms。先收束到局部纸面；约480ms按钮落击联动朱印起势，约552ms形成朱砂实印峰值；约672ms开始短金笔向外迸散；约960ms起自然衰减，结束后切场。手机印面约78px、桌面112px，并有短暂落印尺度回弹；白字朱印和局部纸底取代衣纹上的小线框。图形始终在肖像下半部，不盖脸、姓名、技能或按钮。
- **按钮本体**：移动的是 SceneView 原按钮面和原文字，放进纯视觉容器；原命中矩形保留在原位，未做替身按钮。约216ms压缩蓄力，随后跳起、短暂腾空，再落击压扁并复位。56px按钮最多抬升8px，44px短屏按钮收为5px；横向最多伸展4%，守住既有底栏间隙。落点有一次局部短冲击笔触，不加全屏震动/变暗/频闪。

总池仍是手机32/桌面64张图片，原因是已有节点足够用于此次空间、对比和节奏改造，并非把旧预算当硬上限。C借十个方向碎笔和一个原软刷，B借六个；动态结束归还颜色、旋转、尺寸和前后层。仍使用一个现有 Phaser Tween 时钟，没有新引擎、依赖或素材。六人共用，仅保留既有身份色的细微差别。

## 触发、入场和清理

英雄ID变化才触发B；路线预览、选路线和取消都不触发C。C及按钮重动作只在原有确认、解锁与保存全部成功之后触发。

默认会自动完成并入场，不需要第二次确认。演出期间按钮显示“直接入场”，再次点按或 Enter 只请求略过演出，最早在按钮落击恢复后约660ms结束；它不会再次调用创建新局或改变路线/存档。这样给默认审样足够时间，也不强迫用户等完整1200ms。

减少动态：不播放按钮/笔触/金粒动画，只短暂显示静态朱印及已选定文字，按钮位置和scale不变。初始减少动态和演出中开启减少动态都实际核验。取消、连续六人切换、失焦、缩放、场景退出清理，以及 Scene destroy 自身监听释放均覆盖。

`checks/report.json` 记录10个针对性场景。确认中的失焦、缩放、退出、开启减少动态、重复点“直接入场”、初始减少动态均观察原 Promise：完成次数1；原控制器、存档revision与state不变；退出回title不自动进店，其余只进一次商店。原按钮视觉容器最终位置0/0、scale1/1，旧Tween、静态计时器、借用节点及监听均释放。保存故障注入不会出现确认动作。

## 验证依据与限制

`before/report.json` 是 main 的实际源哈希与原速基线；`after/report.json` 是已提交源码的录像摘要、固定命中框/可视按钮位置/文字避让与性能采样。逐帧原始数据压缩在 `*-frames.json.gz`。`index.json` 将最终源文件哈希、测试及媒体校验对应起来，不能把记录头中的父提交误当作测了干净main。

本地实际跑过类型检查、相关3文件22项测试及生产构建，结果见 `typecheck.txt`、`tests.txt`、`build.txt`。另跑双端原速自然结束与上述10项针对性浏览器检查，没有为此重跑六人整局/全游戏矩阵。最终分支SHA的自动CI以新PR记录为准。采样同时记录可见前后层、池大小、最大绘制命令数、待机paint耗时与确认帧间隔；这包含浏览器录制/渲染快照开销，不是实体设备性能认证。

首次检查脚本把场景内置插件的update监听也要求归零（4≠0），原始FAIL保存在 `checks-first-fail/report.json`。随后改为观察本模块listening及相对基线监听差，未为该脚本错误改生产逻辑。
