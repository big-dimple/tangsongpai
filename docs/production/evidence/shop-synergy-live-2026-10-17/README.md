# 商店候选动态配合提示

基线 `a14d3b55d456d9bafb75d031347985288404eff8`；独立分支 `dev/shop-synergy-dynamic-20261017`。源码只改 `ShopScene`、`ShopSynergy` 和专属 `ShopSynergyPreview`，另附专属测试。未改公共详情、其他场景、资源、领域命令、价格、存档或 RNG。P08 保持 in_progress。

鼠标悬停候选时，按真实购后余额计算条件交集，相关已持牌显示按实际卡框尺寸绘制的温和金色呼吸与“可配合”标记，气泡说明已持卡名与短理由。触控第一次点商品选择预览，再点同一商品进原详情；长按仍可直接进详情。详情首层列逐张短理由，展开规则有完整条件解释。无交集、金币条件互斥、未知条件、同名或满槽未指定替换对象时不造配合。已持轨折叠时气泡列出真实已持卡名，不伪造屏幕上不存在的卡框。

换候选、换页、换货架、刷新、购买、重绘、进入详情、Escape、指针取消、窗口失焦/后台、动态设置变化及离店时清理本次对象与 tween。减少动态使用稳定金框和理由。候选提示占用小屏原鼠标放大提示的窗口，已持卡悬停放大与详情看图保留。

父级 dot 追加“秦琼买始终如一”负例后，按实际 `discards-used=0` 钩子与当前弃牌技能身份接入明确取舍：**走不弃牌打法可用；发动秦琼弃牌技能会停用本场加成。** 候选气泡、购买详情首层及 PC 商品说明同步，小屏商品短句为“不弃牌可用；弃牌技停用”。不因英雄名或“倍率”关键词点亮；旧身份不虚构当前主动技能。

本地结果见 [status.json](status.json)：最终 31 项定向商店单测及1项新增受控存档导出校验通过，`npm run build`（含类型检查）通过；五个受控存档通过领域不变量及 checkpoint 校验。失败环境输出保留，依赖补全后重跑通过。此前本地 UI runner 在 Vite SSR 初始化超时，尚未启动 Chromium 或取得动态截图；收到用户改由 dot 全局试玩后停止并移除临时浏览器脚本，未重跑截图矩阵。
