## 缺口核对与实现

先核对 DELIVERY_PLAN 原408–425、ShopScene 原574–587/832–833、ConsumableDialog 当前 handOrder 选牌与 GameScene 入场/库存入口：基线确实没有把已购指定实例带入牌桌的 UI 意图承接；原买来使用直接打开商店全副牌目标。未重复实现已有当前手牌能力。

- 道具页“买来使用”在购买保存后提供“现在改牌组”（保留原主选择）、“带入牌桌 · 选手牌”和“继续经营 · 保留工具”。买来存着仍回已有工具页。普通购买回执保留原“立即使用”，增加独立带入选项；取消后也可从购物结果再选使用位置。
- 仅支持同时允许 shop / await-input、当前模式允许、以扑克牌为目标的工具（cards / card-sacrifice / card-or-joker）。升级牌型、全副操作和商店/牌桌专用工具不假装是当前手牌改造。
- 意图只携带 runId、stageIndex、购买后序号和确切 instanceId。复用 BuyOffer / BuyBasicTool → LeaveShop → EnterStage → UseConsumable。意图不写存档、不自动选牌、不自动耗用；选定目标后仍需确认。
- GameScene 仅局部接线：核对唯一离店/入场序列，等发牌结束、可写、无补牌/演出且 B05/关卡说明关闭后，一次打开原 selector。取消后不重开；序号/阶段/实例变化则丢弃。冷恢复不恢复 UI 意图。
- 购买/离店/使用保存失败沿用原候选保存和菜单重试；离店重试入场后不复活临时工具意图，工具保留。主线不更改价格、RNG、规则、数值、存档身份或资源。保护树清单见 audit.json。

## 实际浏览器证据

`node harness/r03-carry-tool.mjs`，系统 Chromium、软件 Canvas、DPR1，PC1366×768鼠标、390×740和320×568触摸。全部12组 PASS。390主线使用正常动效，另两尺寸为低动态。受控商店库存/金币/同名旧工具先通过严格 checkpoint 校验，再通过实际 DOM/Canvas 操作购买、离店、入场、选牌与使用。没有用脚本替代产品命令。

三尺寸均实际完成：2金买入往上挪 → 取消/Escape/继续经营（完整保存不变）→ 从购物结果重新明确带入 → 发牌后仅列当前8张手牌，零默认目标且确认禁用 → 选8♦、查看8♦→9♦ → 取消再手动打开该确切实例 → 双击确认，只消耗新购件，同名旧件保留。手中原有9♦，使用后实际形成两张9；audit.json独立从完整终态核对。购买、携带与确认也使用连点输入。

各步骤用同一个原 SavedRun、applyCommand、保存候选和内存 SaveStore 重放实际命令，与浏览器完整 state、journal、storage（current/previous/checksum/revision）逐字段相等，包含完整 RNG。summary.json保存每条命令与结果；report.json.gz保留完整主线初终快照；audit.json列出最终同点手牌ID。

另9组覆盖：普通回执立即使用、普通回执直接携带、商店全副牌立即使用、买来存着与冷恢复、基础自选购入、B05前后两层说明、购买失败与重试、离店失败与重试/冷恢复、使用失败与原保存重试。所有路径均按原命令重放核对。B05两张截图证明原入场和“这一手怎么接”均先呈现，关闭后才出现工具目标。
