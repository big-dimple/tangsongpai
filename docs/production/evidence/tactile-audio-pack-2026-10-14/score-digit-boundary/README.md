# 独审返修：合法大整数声音分档

输入提交：`89ba7054271eab0af6753a50ea9661ae321067bb`，仍在PR179原开发分支。本轮是独立审查指出的合法输入边界修复，**不是已复现的常见自然局故障**，没有新增自然局或发生频率证据，不改领域数值规则。

## 复现与修改

领域 `src/domain/rational.ts` 导出的 `MAX_INTEGER_DIGITS=4096` 允许4096位整数；最终分数是bigint的十进制字符串。原声音校验写死最多309位，因此合法310位及以上金额落回普通award。先用现有Rational构造真实合法整数再取floor().toString()，在修改产品前运行新增边界检查：[before-FAIL](before-FAIL.txt)有四个失败——310/4096位分档都返回普通award，对应两个实际AudioEngine入口都只有三层而不是万亿六层。309位与4097位拒绝对照保持正常。

产品只改 `src/audio/mixPolicy.ts`：只读导入原 `MAX_INTEGER_DIGITS`，在同一上限内严格验证非空ASCII十进制字符串，再按去掉前导零后的位数选原配方。既不转Number也不对音路做BigInt运算，不可能因浮点溢出变成Infinity或丢精度。领域常量、Rational算法、身份、保存、计分、场景、配方、加载和音量均不改。

专项测试覆盖309/310/4096位正例，4097位领域拒绝与音路降级、空/符号/非整数/科学计数法/换行等非法输入；310/4096位经过AudioEngine实际创建原六层万亿配方。首次修复后额外拍点精确等号把1+0.36与1.36的二进制表示差异误判，日志留在[fixture-float-FAIL](fixture-float-FAIL.txt)。删除与本位数合同无关的该精确浮点断言，保留六层数量和全部voice的万亿语义断言；产品不因此改拍点或时序。
