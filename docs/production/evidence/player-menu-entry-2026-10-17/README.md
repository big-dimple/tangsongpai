## 根因与已改行为

修复前实际复现：同一干净隔离上下文打开两个首页，均无任何存档。第一页没有新局也持有 `tangsongpai-writer`，第二页取不到锁，菜单自动弹出“另一页面持有写入权”。[修复前实际画面](before-empty-second-tab.png)。此外，旧代码把 Web Locks 请求异常吞为false，菜单再把所有false都解释为别页占用；IndexedDB首次打开失败的Promise也会永久留存，重试无法重新打开。

现在空首页先读存档而不占锁，真正开始保存新局才申请。已有进度仍使用排他锁和原IndexedDB事务revision比较，真正并发时以“在这里继续”交接并重读最新完整进度；浏览器自动释放的旧页锁可正常重新申请。锁接口缺失或拒绝时沿既有revision保护工作，不误报别页；实际存储失败独立提示并可在同页重试。空首页打开后若另一页已新存进度，开始操作先读取该进度，不盲目替换。

菜单首层只保留有局才出现的继续、新开一局和直接可用的音量/动态/速度/振动设置。图鉴、全屏、当局查询归入一个“更多”；导入导出、版本和开发回放移出玩家菜单，底层存档API保留。开始替换旧局仍在选角最终确认时确认一次，取消不改变原局。主次动作统一宽度；保存失败时才显示必要重试/取消操作，不暴露写入权或接管术语。

用户随后报告PC菜单隐藏后点不开。本候选已取消两级箭头/隐藏entry，恢复常驻原生“菜单”按钮，保安全区12px内缩、PC64×44/小屏至少44×44、独立可点击层级；宿主不拦牌桌指针，按钮和原生dialog明确接收指针。关闭/Escape仍回到同一按钮，键盘仍是原生button。指定PC故障未在浏览器继续复现，真实遮挡/裁剪/边缘命中仍待远端实测，不能把本次代码修复和DOM模拟签成实际PC已通过。
