## 命中清晰度与标签避让修正

父级实际查看原秦琼／刘娥命中帧后指出数字拉糊与红线贴近标签。原六人证据继续证明眼图映射、原字节、提前加载、眼区稳定及真实结算；原命中帧不再作为数字清晰度／装饰避让的最终画面。

- 原因：`crispText` 只按 framebuffer 密度生成字体位图，1× 的位图被放大约 1.54 倍；来源采用的名义图片框比实际图片高，旧连接线的水平段位于标签行附近，而且一直留到数值峰值。
- 最小修正：仅高光数值声明峰值采样尺寸，文字位图提前按 `ceil(framebufferDensity × peak)` 准备，拟合后不会退回静止分辨率；动画逐帧只变换已准备的位图，并按实际 framebuffer 对齐。默认文字采样不变，不逐帧重建字体。
- 来源改取真实图片边界，标签以同一局部坐标中的实测文字 bounds 保护；连接线走标签上方与列间空隙，留 7px 裁切余量，实际图片另留 2px 余量保护飞入标签，采用 1px 短飞入，在到达时淡出，不在峰值留下边角框。数字布局槽位、峰值、到达时点与结算合同不改。
- 只补秦琼、刘娥两个 390×844、1× 的实际 GameScene 单手，保留 before／flight／impact 画面：[秦琼命中](clarity-fix/screens/touye-impact.png)、[刘娥命中](clarity-fix/screens/erxiang-impact.png)、[核验数据](clarity-fix/runtime.json)。没有重跑六人或尺寸矩阵。两例的数值纹理分辨率均为 2×，覆盖约 1.54 峰值；眼区不移动，实际 f09 事件及完整保存状态仍与规范命令一致。
- 对上述三个阶段的实际 PNG 做像素检查，标签 bounds 外扩 6px 内红色像素均为 0；旧两张命中图在相同范围各为 23。补查飞入帧时发现浮动值曾擦到眼图边缘，已将真实眼图加入图片避让；修正后三阶段眼区像素哈希一致。
