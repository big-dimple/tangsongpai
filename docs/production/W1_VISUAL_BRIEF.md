## 3 四项W1有限调整

### P1 比较牌桌空间分配

**映射：U03 → W1。** 任务是看目标、识别全部九牌、选牌、检查待出牌、执行。先调整上方空槽/状态、中段空白与下方手牌/动作的预算，保留独立出牌区、清楚角标、文字动作及次数。

- 候选A：紧凑状态/槽位，独立出牌区，九牌单排错叠，选中牌只在出牌区完整放大。
- 候选B：同样信息预算，九牌5＋4错层两行，牌角无遮挡。不用3×3铺满屏替代比较。
- 同九张牌、同已选组合、最长合理文本、同竖屏尺寸并排检查，主操作至少48px，必要规则文字不压缩丢失；随后才验实际点选。
- 任一牌角被遮、出牌区变成装饰空白、需滚动才能出牌、文字或主操作被挤掉即失败。静态看起来大不算获胜，也不为人物装饰牺牲识牌。

### P2 突出真实成长与生效时点

**映射：U06 → W1。** 任务是回答“当前保存多少、这次实际读取多少、何时再增长”。保留原画、完整规则、适用牌型、上限和重触不多长等限制。

- 候选A：条件、本次效果、保存成长分三个短层次；候选B：标题下突出“当前保存”信息，再用相邻两行说明触发及下手生效。
- 完整边界可展开，短版不能裁掉触发条件和上限；购买视图减少重复时序表达。
- 用+0、已有成长、封顶、未读取四种明确状态比较首屏发现性。保存状态与已结算trace分别提供依据，不能将保存值擅自称作本手已读取。
- 不显示预计总分或把预计增长写成已结算；没有实际读取事件时明确未读取。为缩短文案漏掉资格、上限或生效时点即失败。

### P3 分开商品比较与最终确认

**映射：U03、U06 → W1。** 总览比较三件价值，详情决定是否付款。当前三图未覆盖三货总览，所以这里只提出待验证候选，不预记总览失败。保留现有实付、余额变化和朱红确认/取消层级。

- 候选A：三张短卡同屏呈现名称、价格、收益/条件摘要；候选B：三条紧凑商品行加选中详情，减少逐个全屏查看后的记忆负担。
- 同一组三商品包含长名称和长条件，静态核价格、收益、限制及付款上下文，主操作至少48px。独立工具、长期物品和已有构筑仍需保留。
- 不把牌桌九牌和商店三货强塞同屏。只能看一件、省略条件导致失真、付款前看不到实付余额、三列压成不可读小字即失败。

### P4 区分返回 排序与出售

**映射：U03、U06 → W1。** 任务是查看后关闭、移动可用/不可用、主动出售。保留明确文字关闭和正常禁用态，不因灰色推断故障，不用纯图标替代动作。

- 候选A：关闭作为明确的主要返回，排序与出售放管理区；候选B：保留单行，降低排序权重，拉开出售与关闭的位置/语义。
- 主返回至少48px；先静态核寻找路径和主次，后续才检验真实命中及出售确认。不能用截图声称误触改善。
- 关闭更难找、出售比日常返回更抢眼、增加退出步骤、四等分牺牲主操作尺寸即失败。

## 4 输出与停止条件

W1下一步只需把四项候选转成同状态、同尺寸的比较任务；静态稿验证层级，真实输入验证可点性。通过一个再收敛一个，不新增机制、插画批次或一套主线。工程负责人记录48/44px触点、正文清晰度及中断/返回结果；用户只需在真实候选关键节点评价观感和操作。

任何结论必须绑定实际runtime、视口与状态；八牌静态图、购买详情或软件Canvas不代替九牌、三货总览、真机或完整交互验收。本简报归档后进入既有W1执行任务，不继续扩写新方案。
