# 基线审查：现在必须纠偏，但不需要全盘重写

审查日期：2026-09-30。仓库：big-dimple/tangsongpai。固定提交：`9fd6e0bdb20c7e6114e045ca336c27afe5d47e9e`（19:55:55 UTC+8）。本报告不覆盖该提交之后的代码。

## 结论

这是一个有工程雏形的 Phase 2B 原型，不是已经形成成熟构筑体验的产品。最危险的不是素材不够，而是把“能选牌、能加分、有商店、CI 绿了”当成了核心玩法完成。照旧路线直接叠 Boss 和特效，会把规则、移动端和状态缺口带进更多内容。

保留 TypeScript/Phaser、SeededRng、普通牌型判断、已有纯函数和素材源流水线。重做领域边界、完整局状态、计分合同、手机布局与验收方法。先灰盒证明构筑的取舍与手感，再做视觉金样，最后扩量。

## 必须先改的发现

### F01 / P0 / DESIGN：文档协议会把错误实现固化为设计

证据：根 AGENTS 要求“先按真实实现修正文档”，且“代码…高于文档”。这会让新 Agent 遇到冲突时先降需求而非修错误。TODO 写“只放未完成”，却以大段已完成资产清单置顶；handoff 的唯一下一步直接进入 Boss。

整改：D01–D08 明确权威层级；审查快照不可改写；plan 为唯一状态；有范围/依赖/验收的工作包。关闭证据：新会话只读入口和 R00 相关文档，能准确说出当前未完成事项，不继续旧 Boss 路线。对应 R00/R06。

### F02 / P0 / DESIGN：普通牌没有点数价值，计分集合未定义

证据：`src/scoring/scoreHand.ts::BASE_SCORES/scoreHand` 只由牌型给基础分；`handEvaluator` 返回全部所选牌；`JokerEngine::countFaceCards` 统计所有所选 J/Q/K/A。因此普通单张 2 与 10 在无相关能力时基础相同，多带的非成型牌又可参与铁算盘。

这不是违反旧 GDD 的 bug，而是需要明确升级的设计。新合同必须区分 playedIds、scoringIds、heldIds，普通牌提供点数，效果标明针对哪一集合。关闭证据：RULES 的成对带杂牌、单张、持牌、复制牌等金样例逐事件一致。对应 R02。

### F03 / P0 / DESIGN：装备顺序没有数学意义

证据：scoreHand 将全部 heatBonus 求和、全部 multiplierBonus 求和、全部 finalMultiplier 相乘。调换 Joker 顺序不改变最终结果。逐张动画看似连锁，但不是前一张影响后一张的连锁。

整改：r2 使用有序时点与逐事件 accumulator；同一阶段左到右的 +倍率 与 ×倍率必须按顺序计算。例：初始倍率 2，+3 后 ×2 为 10，×2 后 +3 为 7。不是只加拖拽 UI。对应 R02/R05。

### F04 / P0 / GAP：缺少完整构筑闭环

证据：GameScene 只有出牌，没有弃牌、牌组查看/改造；商店池五张、槽五个，未出售/替换，`shopPool` 只排除已买。最终倾向全部买齐，难以形成长期放弃、转型和适应。

整改：补有限弃牌、牌组持续改造、买卖与五槽机会成本；扩内容前用 24 张牌验证多条路线。关闭证据：至少三种不同构筑可以过灰盒；买卖/跳过/保留资金都有合理使用案例，不能靠某一张通吃。对应 R03/V00/V01。

### F05 / P0 / GAP：RunState 不是完整一局

证据：`src/run/runState.ts` 只有 seed/角色/关索引/总热度/gold/jokerIds。手牌、牌堆、关内热度、次数、货架、刷新位置、RNG 游标都在 Scene。每关重建标准牌组。不能从这些字段可靠恢复关内或商店；未来牌组改造也无持久载体。

整改：完整序列化状态、领域命令、原子结算/存档和版本化；同一入口供玩家、机器人与回放。对应 R01/R03/R04。

### F06 / P0 / CONFIRMED+算术：手机“能点中”不等于能玩

证据：`src/main.ts` 1280×720 FIT；GameScene 按钮高 58，Joker 描述 10。390×844 视口理论缩放为 0.3046875，游戏画面高 219.375 CSS px，按钮高 17.671875 px，描述约 3.046875 px。这是源码推算，不是设备量测。

整改：独立竖屏布局，按 CSS 像素校验字体和命中区，横竖旋转保留状态。不能仅换 RESIZE 常量而保留全部硬坐标。对应 R05；需真触控完成完整一局。

### F07 / P1 / PROBE+RISK：EffectQueue 取消/重入不成立

证据：`clear` 只替换待执行数组；正在 await 的效果不取消。`drain` 发现 running 时立即返回，并不等待原任务。来源摘录探针证明：第二次 drain 在新效果尚未执行时已 resolve，释放旧效果后，旧 drain 会继续消费新队列。

GameScene 又允许结算时“重新选角色”，动画 Promise 只在 onComplete resolve，缺少 shutdown 取消与 playSelected 的 finally。**具体 Phaser 重进后的锁死/串场尚需实机复现**，不能只凭探针断言已经线上发生。

整改：generation/AbortSignal、统一结算 Promise、停止时显式 settle，规则提交与 UI 清理解耦。退出后旧回调不得触碰新局。对应 R04。

### F08 / P1 / CONFIRMED：平衡机器人不等于实机

证据：`tests/balance.test.ts::playStage` 用 splice(0)/shift，GameScene draw 用 pop；机器人候选评分固定 luckRoll=.5，最后 rng.next() 的实际值丢弃。两者同 seed 不是同一盘；测骰爷会把随机结果固定在失败分支。当前门禁只跑二响/阿燥、10 个固定 seed，且仍是单步贪心。

机器人枚举 1–5 张全部子集，旧 handoff 的“不会主动打单牌”解释不准确；它缺的是长期策略，不是根本没枚举单牌。整改：领域命令共用、随机真结算、公开信息选行动、留出 seed、六角色及多策略。对应 R01/R06/B00。

### F09 / P1 / CONFIRMED：自动化覆盖不能支撑当前质量声明

证据：`harness/screenshot.mjs` 的 mobile 仅 hasTouch=true，实际点击仍用 page.mouse；只点第一角色、跳过购买、进牌桌，不打牌。CI 只 npm install/typecheck/test/build。已有本机实玩证据在 gitignore 的 shots，仓库无法复核。

整改：保留启动冒烟，但另测购买→出牌/弃牌→过关→商店→失败/胜利，加入真实 touch 输入、资源失败、恢复、中断和构建产物子路径。CI 上传失败 trace，必要成功金样可版本化存档。对应 R06。

### F10 / P1 / CONFIRMED：原图预载比拆 bundle 更应优先处理

证据：BootScene→queuePortraitLoads→CHARACTERS.portrait，六个 PNG 合计 14,285,460 字节；已有六个 avatar.webp 却未被该路径使用。资源包检查的 ≤20MB 是新增包预算，不等于全部首屏预算；也不等于解码后的显存预算。

整改：选角缩略图、HUD 头像、详情高清分级；只预加载当前必要资源，清楚失败回退和实际网络字节。原图移出运行时发布白名单，保留源文件。对应 R05/A02。

### F11 / P1 / DESIGN+GAP：美术资产验收错位

证据：39 GLB、5 档卡框、素材检验已交付，但运行时 JokerRarity 只有 common/uncommon/rare，且资源尚未接入。旧硬约束几乎把每个对象都东方化，缺统一渲染/构图/字重与小尺寸评审合同。

整改：3 档稀有度统一，材质特效与稀有度解耦；2D/2.5D 金样先行，六角色以同一画面语法容纳差异。现有资源先列保留/重加工/暂不采用，不凭沉没成本入场，也不未经目审全部作废。对应 A00–A03。

### F12 / P2 / CONFIRMED：资产“检查”有写副作用

证据：`tools/blender/inspect_asset_pack.mjs` 即使未 --optimize 也重写 manifest；只检查 alpha 通道存在，不代表边缘/有效透明度正确；只遍历清单，不证明没有未列资产。若干直接 import 依赖只由 CLI 传递引入；三角预算还设了下限。

整改：--check 只读、--update 显式写；直接依赖锁定；清单与文件双向检查；面数仅上限/收益约束；增加帧/裁切/透明边缘的真实预览。技术校验通过与美术批准分开。对应 A00/R06。

### F13 / P2 / RISK：HUD 仍有裁切缩放不一致

证据：`portraits.ts` 已解释并使用 setScale 避免原帧裁切后的非等比缩放；GameScene 的 HUD 仍 setCrop 后 setDisplaySize(58,58)。已有裁切数学测试不覆盖 Phaser 实际呈现。需在原图与独立 avatar 上实测，不能重复引用过去提交“已正常”当本次证据。对应 R05。

### F14 / P1 / GAP：声音与信息反馈还只是占位

证据：AudioEngine 只有几种 triangle tone，无持久音量/静音、音乐层级、速度/减少动态选项；选择不提供明确预计牌型/计分集合，来源明细是结算后的文本堆叠。不是增加更大爆炸就能补上节奏。

整改：可追踪筹码/倍率仪表、数字阶段变化、明确声部、可快进与静音、失败复盘，先保可读性。对应 R04/R05/A03/B01。

### F15 / P2 / CONFIRMED：类型断言和默认值隐藏错误输入

证据：JOKERS = JSON as unknown as Definition[] 无运行时内容校验；scoreHand 漏传 jokerIds 默认装备全部；buyJoker 不验证请求是否属于当前货架。这在离线游戏不宜夸大为远程漏洞，但会破坏恢复、机器人和测试的可信度。

整改：schema/穷尽分派、显式装备数组、命令验证 phase/offerId/commandSeq，购买重复提交幂等。对应 R01/R02/R03。

### F16 / P2 / DESIGN：奖励与角色意图需要一起平衡

证据：每剩余出牌奖励 2 金，谢幕人最后一手才 ×2；阿默被动围绕单张，但普通点数缺失；骰爷每手强制硬币判定。不能由两个角色的 10 seed 测试得出六人都体验合理。

整改：角色从奖励结构、出牌/弃牌选择和可控风险共同验证；r2 的具体能力与上限写在 RULES，调参记录收益/代价。对应 R02/B00。

发布之前必须补齐：完整局与恢复、实际触控、真实素材小尺寸审查、目标机性能、六角色/留出种子平衡、真人对标。没有这些，不给“达到 Balatro 水平”的结论。
