## 事务、身份与恢复

`BuyPokerPolychrome`将扣18金、改一张版次、共享额度与机会购买凭据放在同一领域候选里，由原`SavedRun`／IndexedDB提交后才发布。重复命令沿既有去重；双确认在UI与保存队列均有门。写盘失败不发布任何改牌／扣款，菜单重试原候选，不能重新抽机会。

机会ID由runId／真实通关数／关卡派生，绑定真实通关与购买命令指纹。已购凭据在有界journal截断、甚至空journal后仍可校验；删除购买记录、改来源ID、重开机会或伪造下一间隔均拒绝。不是防御任意有权限重写整个存档并重造全部指纹的攻击系统。

新身份附加`poker-encounter-v1`合同哈希，保留全部旧身份与Boss救场映射。旧存档继续旧规则、旧身份重试仍旧身份；不注入奇遇字段，不改旧共享JSON。旧构建不能读取新身份档是显式版本边界；回退构建前应保留原始新档，不能删字段冒充旧档。

DOM事件通道：`tangsongpai:poker-encounter-view`，`CustomEvent.detail`为冻结的`PokerEncounterVisualEvent`。内含稳定事件id、机会id、只读view、可选targetId/reducedMotion。view只有当前金币、固定价格、合法性说明、存活扑克的公开属性与已保存购买账单；没有未来间隔、抽牌顺序、RNG或dispatcher。

事件为`EncounterEntered`、`SelectionChanged`、`PurchaseCommitted`、`GrantPresented`、`Skipped`、`Exited`、`Restored`、`ReducedMotion`。普通确认真实保存后才发`PurchaseCommitted`与静态结果`GrantPresented`。同店再次查看、冷恢复和菜单精确重试后的重入只发`Restored`并展示账单，不补播成功。稳定id允许视觉自行去重，重进不能刷新奖励。取消确认只是回到选牌，无领域动作。后续动画可以改变`GrantPresented`的画面到达时点，不能延迟／决定事务或在结束回调再派奖励。

Astra由父另派中档任务，本轮没有启动。不得改领域、存档、随机数、价格、结算或选角；不恢复旧苏轼烟雾。视觉依国风手绘墨线、纸张、深青绿、克制朱砂，保留蓄势→峰值→衰减；不满屏发光圆点，不挡确认／取消。减少动态走静态结果。阶段2须PC横屏和手机竖屏原速录像并核对恢复／离开清理。视觉失败或监听器移除应回退当前静态界面，已保存结果不受影响。规则修改若有需要另议新身份，不夹在视觉提交。
