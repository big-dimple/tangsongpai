# 正式工作包合同

当前状态/依赖只见[plan.json](plan.json)，唯一派工为[Q1–Q4](DELIVERY_PLAN.md#当前统一执行计划)。下列32包保留既有范围与正式退出条件，不重复维护状态；已完成包不因旧open PR或旧“下一步”重开。

本轮P08使用Q1–Q4。旧正式M0–M9、旧音画M1–M3是不同历史命名域，原定义与检查点完整见[清理前工作包](history/planning-before-20261020/WORK_PACKAGES.md)，不能把“需真人/素材批准”扩成所有工程的永久等待门。Git/产品权限只按本会话，不从旧合同推导。

## R00

**采用基线与复现证据。** 无前置任务。输入 AUDIT、DECISIONS、现有 CI 与仓库实际 HEAD。范围限工作流程/证据/必要环境修复，不加新玩法。

步骤：记录当前SHA/分支/dirty状态；比对审查SHA后新增提交，逐项确认发现是否仍成立；运行 npm ci、verify、verify:smoke；登记真实设备/浏览器；用当前原型保存选角/商店/牌桌截图及一手出牌和中断现象；生成六头像/原图和资产总览的可审查预览（可把完整GLB预览交A00，不假装完成）。检查依赖告警的具体链，不使用force修复。

验收：基线证据对应真实被测SHA，所有不能运行项明确列出；F01的旧指令被新入口替代；后续AI知道先R01而不是旧Boss。只需本计划明确被采用，不必把每条初始数值都逐项问用户。

产物：R00证据JSON、支持矩阵、差异复查表、相关截图/日志路径；plan改下一包。阻塞：仓库无法读取/存在不能安全处理的别人改动，保持BLOCKED，不reset。退出：可复现当前原型即可，不声称其体验通过。

## R01

**唯一领域命令、完整状态骨架与RNG。** 依赖R00。重点路径src/domain、src/run、src/core、GameScene/ShopScene薄适配、src/testing。

先按r1语义抽出状态与reducer，确保入口迁移不同时偷偷改数值；再为r2保留显式版本。状态包含真实牌区、关内资源、货架与RNG游标；抽牌方向只定义一次。UI和机器人通过同一接口，角色资源URL移出纯规则模块。

新增test:domain：非法ID/重复ID/过期序号/错phase不变状态；同命令重试幂等；固定shuffle/RNG向量；UI命令日志与headless回放一致。将旧机器人pop/shift与丢弃luckRoll问题变成会失败的回归用例。模拟器仍可用简单策略，但不能另写一套游戏循环算分。

验收：规则目录无Phaser/DOM/Audio/Date.now/Math.random依赖；现有原型仍可进入/出牌/过场；相同版本命令流stateHash相同。证据含一次完整三场的领域日志以及新增测试输出。非目标：新Boss、全内容、重画UI。回滚：恢复旧适配器但保留新测试和差异记录，不宣布R01完成。

## R02

**r2牌型、计分、六角色与内容schema。** 依赖R01。输入RULES、CONTENT基础条目、DECISIONS D02。

实现played/scoring/active/held集合、有理数服务、12牌型、明确角色时点、有序JokerScore、不可变trace、成长实例和有限重触发。移除漏传jokerIds自动装备全部的默认值，所有调用必须显式给装备。骰爷改为可选押注，其他r2差异按合同列入迁移记录。

新增test:rules与verify:content。G01–G15逐事件精确断言；增加四张顺/同规则尚未启用时的拒绝/普通识别用例、A2345与错误跨A顺子、复制实例与同ID拒绝、数值10^1000、分母边界、r1/r2版本隔离。先实现引擎所需有限hook，不生成72张无效JSON。

验收：顺序变化真的能改变数值，杂牌不会偷偷计分，预览不动真实随机。修订旧单测明确标记规则升级，不以旧预期改了就叫bugfix。产物含trace金样文件和schema错误反例。非目标：声画精修、全新架构框架。

**出弃牌、持续牌组与买卖经济。** 依赖R02。范围domain/run/shop与最小可操作UI。

新增test:run：买卖同实例/满槽/不足金/空池/重复奖励；同seed同货架/刷新恢复；弃牌不更新上手牌型；牌组改造跨场不丢；最后一手刚好过关；无牌可抽合法结束。UI至少可看懂库存、选择、金币和下一步。

验收：不借调试hook即可买入、出牌、弃牌、过关、再逛店、出售替换；程序不能靠直接改state模拟通过。保留可重放操作日志。非目标：完整高难度与所有Boss。回滚保持存档版本隔离，不能混用两个经济公式。
