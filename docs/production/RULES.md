# r2 规则合同

状态：r2 设计合同，实现进度与验证证据见 plan.json。D02 明确这是规则升级。机制语义按本文件实现；数值为第一轮可运行的初始参数，尚未验证平衡，不得称为“已校准”。B00 调参只能修改版本化 balance 数据并生成对应表格/变更记录，不得顺手改变触发时点或集合定义。

## 1. 局、章、场与资源

一局八章，每章暖场/正场/压轴三场；最后一场是 Boss。手牌上限默认 8、每次出牌 1–5 张、每场出牌 4 次、弃牌 3 次、最多 5 张唐宋牌、消耗品 2 格、局内长期道具 4 格。所有这些数值来自配置，不散落在 Scene 和测试中。

标准局起始 52 个实例，四花色×2–A，每个实例 ID 唯一。复制牌增加新 ID，可出现同点同花的不同实例；禁止同一个 ID 同时出现在两个牌区。

每场开始从当前持久牌组生成本场抽牌堆并洗牌。抽到手牌上限或牌堆耗尽。已打出和弃掉的牌在本场不再洗回；下一场用持久牌组重新开始。牌组改造改变持久实例，不会在换场被重置成标准 52 张。

出牌成功后扣一次出牌并结算；未过关且还有出牌机会时补手牌。弃牌选择 1–5 张，扣一次弃牌，移动到弃牌区、触发弃牌事件、补牌，不扣出牌、不更新上次牌型。无可抽牌时仍可打剩余手牌；手牌为空且没有可抽牌或资源可产生合法行动时失败。玩家可以提前结束本场认输，须确认。

达到目标立即成功；最后一手达到目标仍算成功。先判过关，再判次数用尽。进入胜/败状态后任何 Play/Discard/Buy 请求均应返回结构化拒绝，不重复发奖励。

## 2. 四个牌集合，禁止混用

- playedIds：本次实际打出，全部离开手牌，包括未参与成型的杂牌。
- scoringIds：组成所识别最佳牌型的牌。
- activeScoringIds：scoringIds 扣除本场被封禁/失效者；这些牌产生点数和一般“计分牌”触发。
- heldIds：出牌提交前留在手中的牌，不含 playedIds。

卡牌只是失效时，仍可参与牌型识别，但不给点数、不触发一般计分牌效果；明确写“打出”或“参与成型”的效果才可看到相应更大集合。所有卡文使用“打出/计分/留在手中”之一，不用模糊的“每张牌”。

普通点数：2–10 按面值，J/Q/K 各 10，A=11。人头牌只指 J/Q/K；铁算盘特例显式写 J/Q/K/A，不把 A 隐藏归入人头牌。

| 高牌 | 最高点数的一张 | 20 / 1 | 10 / 0.25 |
| 对子 | 组成对子的两张 | 35 / 2 | 15 / 0.5 |
| 两对 | 两组对子四张 | 65 / 2 | 20 / 0.5 |
| 三条 | 三张同点数 | 90 / 3 | 25 / 0.5 |
| 顺子 | 五张 | 125 / 4 | 35 / 0.5 |
| 同花 | 五张 | 140 / 4 | 30 / 0.5 |
| 葫芦 | 五张 | 210 / 5 | 40 / 1 |
| 四条 | 四张同点数，不含第五张 | 320 / 7 | 55 / 1 |

玩家手牌顺序属于领域状态。PlayHand 的顺序按 handOrder 过滤 selectedIds 得到，不取鼠标点击先后；拖动手牌或使用排序命令会明确改变 handOrder。成型牌按这个顺序进入计分。

## 4. 一手计分的权威顺序

输入：完整局状态 + PlayHand 命令。输出：新的完整状态 + 不可变 ScoreTrace。一次提交同步完成全部数学与规则状态，不等待动画。

1. 校验阶段、资源和实例；读取本手开始快照，固定 played/held 集合与 playIndex。
2. beforeHand：应用公开 Boss 规则和本手明确的规则替代项，识别牌型与计分牌。不会随机换一种牌型。
3. 建立热度 H=牌型等级基础热度，倍率 M=牌型等级基础倍率。
4. 逐张 activeScoringIds：加入点数、该牌增强及版次，再按装备左到右执行 onCardScore；明确的重触发按第 6 节重走该次点数/增强/版次/钩子。普通点数抑制只停点数，整牌失效则不执行本步。
5. 逐张 heldIds：执行持牌增强、onHeldCard；非计分的持牌不凭空加入普通点数。
6. characterScore：执行角色能力，写入同一 H/M 累加器与事件。
7. jokerScore：按五槽左到右执行各自该时点效果，紧接该槽版次，再处理下一槽。**+倍率与×倍率按发生顺序改变 M，不再分组后统一相乘。** 本体条件未命中或仅有经济能力仍执行有效版次；Boss反序连同本槽版次移动。
8. 计算 floor(H×M)，将非负整数加入本场热度；没有单独隐藏的“最后再乘一遍”字段。
9. afterHand：按原始active计分牌顺序判玻璃破碎，每实例一次；更新成长、手次与角色/牌状态，默认增长从下一手生效。移走 playedIds，处理持久销毁标记、必要补牌、判胜负并生成奖励/商店或失败状态。先成功后失败，幸运当手金币仍在失败时保留。
10. 原子写入新状态、trace、commandSeq，再保存。表现层随后播放事件；取消表现不会取消已生效命令。

静态手牌/次数修正只在进场生成初始资源时应用；中途改变上限不会白送已消费次数。时点内默认按实例槽位/手牌顺序稳定分派。需要不同优先级的效果必须在 CONTENT 明确声明，不靠注册先后来决定。

热度与倍率使用准确的整数/有理数服务，最终只 floor 一次。例如 3/2 与 3/4 不是字符串 toFixed 后重新参与计算。大分数不允许溢出为 Infinity；具体表示、序列化和上限保护见 ENGINEERING。

## 6. 重触发、成长、复制与循环

“重触发一张牌”=再次执行该牌的点数/增强/版次/onCardScore，不重新识别整手，不再次执行角色、整手 Joker 或 afterHand。重触发事件带 rootEventId、retriggerDepth；1.0 最深一层，不允许重触发事件再生成重触发。返场纸的自重触发也只由深度0贡献一次，并与Joker来源共用每卡额外四次上限。

同一牌有多个重触发来源时，每个满足条件的来源各贡献一次，按来源槽位处理。每张牌每手最多 4 次额外重触发，这是明确设计上限，须在图鉴说明，不能暗中丢事件。内容包必须证明自己的最大展开事件数不超过 512；异常超过时回滚未提交命令并保存故障证据，不把截断后的较低得分算玩家失败。

C01/现48定义由内容CLI按有效计分牌1–5、手牌14、Joker5、每牌最多5次执行推导保守上界318<512：计入幸运每pass两检查加两收益、每原玻璃检查/销毁、有效持牌、五槽本体/版次、成长/寿命、利息、道具/补给和救场来源；跨时点使用同一组五个来源，而非拼接不同装备的局部最大值。详细分项由CLI输出，过度计入互斥条件使其保守。此证明替代早期预留估计，不是最大合法组合的实测；纯resolver仍硬限手牌14/Joker5。C02增加定义或改变日志展开时必须重新证明并实测连锁，不能沿用318或截断事件。 C02现72定义及两章B01–B04已单独闭合证明可达资源下最大事件数91，并由真实共享命令达成（纯resolver88、过关规则3）；联合上界保持同组五槽、增强互斥和成功/失败分支，CLI同时保留318保守界及512硬限。91限定当前内容/章节/资源，既不是最大得分也不是自然获取或平衡结论；未知定义、条件改变或Boss池扩展会拒绝沿用，C03必须更新证明及对应金样。实际演出与恢复证据见C02-closeout-2026-10-02.json。

成长状态挂在 Joker 实例，不挂全局 ID。除明确“进场重置”者，成长保留到本局结束；出售后清除该实例。afterHand 的增长默认下一手生效；onDiscard 的增长在随后的出牌生效。

## 8. 经济、商店与跳场

初始金币 6。金币为非负整数；普通场奖励基础为暖场 4、正场 5、压轴 7，加剩余出牌×1，加利息 min(5,floor(本场奖励前金币/5))，再加明确角色/Joker 奖励。失败不发成功奖励。每次奖励带唯一 stageClearId，重试不会重复领。

商店包括三张 Joker、一件消耗品、一件长期道具。Joker 价格 common=4、uncommon=6、rare=8；稀有度抽样权重 5/3/2，不放回。初始店必须至少有一张买得起的 Joker，但不保证指定流派。其余候选和种子可复现。

Joker 可以出售和调整顺序。售价 max(1,floor(实际支付价/2))；免费获得的基础售价 1。五槽满时先明确出售再购买，不能一键吞旧牌。出售有独立确认，购买和移动不共用 pointerdown；售出不立即刷新货架。

刷新第 n 次费用 min(10,2+n)，n 从 0 开始，每店重置；重抽 Joker 与消耗品位，长期道具位不刷新。购买不会让其他位置自动补货。货架不足显示空位；无可刷新候选时不收费。消费和新货架必须在一个领域事务中提交。

长期道具最多四种，本局永久、不可出售；已有者不重复出售。消耗品最多两件，满槽时购买明确拒绝；玩家可主动销毁其中一件，确认后才执行。不能自动卖掉或使用。

暖场可跳过获得下次购买减 2 金的单次券（最低支付 1）；正场可跳过获得公开展示的一件普通消耗品，满槽可改为 1 金；压轴不可跳。跳场不获得成功奖励、利息或 onStageClear 成长。跳场奖励生成于章开始并保存，不允许进入退出刷新奖励。

商店开始/结束是领域阶段，不是 Scene 名称。所有 Buy/Sell/Reroll 验证 phase、offerId/instanceId、余额、槽位、commandId；UI 灰态不是唯一防线。

## 9. 关卡目标与 Boss

## 11. 节目单、难度、挑战和解锁

每章开始从以下四合同抽两项，不重复；可选一个或跳过。只统计该章，奖励章末过关时一次发放：换场大师=用过三种不同牌型 +4 金；一招鲜=同一类型成功打出三次 +4 金；不打烊=章末持有至少 15 金，随机一个已使用牌型 +1 级；谢幕留客=该章任一场最后一手过关，下一店刷新券一张。跳场不算一次出牌。两个合同都不能强制要求玩家用不合法手牌；选后可放弃，无惩罚无奖励。

四难度按顺序解锁，非永久战力：D0 原参数；D1 目标×1.2；D2 继承 D1 且弃牌 2；D3 继承 D2 且初始金币 4、刷新费用额外 +1（最终封顶 11）。挑战使用独立规则配置，不悄悄改普通局数据。
